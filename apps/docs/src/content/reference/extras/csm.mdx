The `<CSM/>` component offers a streamlined convenience integration of the Cascaded Shadow Maps technique, sourced from the Three.js addon.

Cascaded Shadow Maps (CSM) are a technique employed to render shadows with varying levels of
detail based on their distance from the camera. CSMs utilize multiple shadow maps to produce
higher resolution shadows closer to the camera and gradually decrease this resolution for
shadows farther away. This method is especially beneficial when rendering sun-cast
shadows over vast terrains, ensuring detailed and performance-optimized shadow renderings.

## Usage

```svelte title="Scene.svelte"
<script lang="ts">
  import { CSM } from '@threlte/extras'
</script>

<CSM
  cascades={4}
  maxFar={1000}
  lightDirection={[1, -1, 1]}
>
  <!-- Your scene goes here -->
</CSM>
```

For CSM to work, shadow maps must be enabled. Threlte does this by default. **Do not disable shadowmaps** by [`<Canvas shadows={false}>`](/docs/reference/core/canvas#component-signature).

Every prop is reactive. Changing `cascades` recreates the underlying instance, as is changing `fade`
on WebGPU, since both are baked into the generated shader; the rest are applied in place.

<Tip type="tip">
  With `fade` enabled, shadows subtly diminish close to `maxFar` distance, presenting a more
  aesthetic transition compared to an abrupt cut-off. It may be more visually pleasing, but it's
  important to consider potential performance implications. While typically minimal, the
  computational complexity can escalate based on the number of cascades and lights present in the
  scene.
</Tip>

## Renderer differences

Three.js ships a separate CSM implementation per renderer — `CSM` for WebGL and `CSMShadowNode` for
WebGPU — and `@threlte/extras` presents both through the signature above, so switching renderers
does not mean rewriting your markup. One difference is worth knowing:

**WebGL** patches the shader code of every material inside the component, and support is limited to
`THREE.MeshStandardMaterial` and `THREE.MeshPhongMaterial`. **WebGPU** drives a single
`THREE.DirectionalLight` through a shadow node instead, so every material that receives shadows
works.

Wrapping your scene in `<CSM>` is only required on WebGL, where the component collects the
materials to patch. The `children` snippet exists on both so the same markup works either way.

<Tip type="warning">Setting `castShadow` property on any lights in a scene with `<CSM>` enabled leads to crashes.</Tip>

## Custom splits

Pass a function as `mode` to compute the cascade splits yourself. It receives the cascade count and
the near and far plane of the camera, and returns one split per cascade as a fraction of the frustum
depth, the last of which should be `1`:

```svelte title="Scene.svelte"
<CSM
  cascades={3}
  mode={() => [0.05, 0.3, 1]}
>
  <!-- Your scene goes here -->
</CSM>
```

## Visualizing the cascades

Bind `csm` to get at the underlying Three.js instance, for instance to drive a `CSMHelper`:

```svelte title="Scene.svelte"
<script lang="ts">
  import { T, useTask } from '@threlte/core'
  import { CSM } from '@threlte/extras'
  import type { CSM as CSMRef } from 'three/examples/jsm/csm/CSM.js'
  import { CSMHelper } from 'three/examples/jsm/csm/CSMHelper.js'

  let csm = $state.raw<CSMRef>()
  const helper = $derived(csm ? new CSMHelper(csm) : undefined)

  useTask(() => helper?.update(), { autoInvalidate: false })
</script>

<CSM bind:csm>
  <!-- Your scene goes here -->
</CSM>

{#if helper}
  <T is={helper} />
{/if}
```

## Providing a fallback

You may want to use a regular `<T.DirectionalLight>` when CSM is not enabled,
for instance if you are developing a game and want to support low-end devices by
disabling shadows altogehter. You can do this by using the `enabled` prop and
the `fallback` snippet:

```svelte title="Scene.svelte"
<CSM enabled={settings.shadows}>
  <!-- Your scene goes here -->

  {#snippet fallback()}
    <!-- Will be mounted if settings.shadows is false -->
    <T.DirectionalLight castShadow={false} />
  {/snippet}
</CSM>
```
